# Changelog

## 1.10.0

### Added
- **Dashboard panel, pain strength in the card "Today":** a row 0 to 10 saves the strength of the day with one tap (shown while a period is running or pain was logged recently; a second tap on the same number clears it; undo is offered). Not shown in discreet mode.
- **Dashboard panel, "Pain & Mood Trend" shows the strength** (0 to 10) per day instead of only counting pain types; days with pain types but no strength are marked as unrated.
- **Dashboard panel, widget "Next 7 days":** period, fertile window, ovulation, pill pack, supplies and reminders of the coming week in one list. Not shown in discreet mode, in pregnancy, menarche, menopause and postpartum; off in the "young" preset.
- **Dashboard panel, widget "Search history":** search the logged days by text and category (symptoms, mood, pain strength ...) over 30, 90 or 180 days or everything loaded; a hit opens that day in the quick log. Not shown in discreet mode.
- **Day dialog of the calendar card animates:** the dialog for editing a day grows out of the tapped day and shrinks back into it when it is closed. When the card is scrolled out of view, it shrinks away too and grows back on return (what was typed stays). Nothing moves with "reduce motion" on.
- **Dashboard panel, swipe on the phone:** swiping sideways switches to the previous/next view (over the calendar card: the month); pulling down at the top reloads the history, the household bar and the saved settings.
- **Dashboard panel, views as text:** in the edit mode a view can be copied as a short code and imported again (other device or profile). Invalid codes change nothing.
- **Dashboard panel, light/dark and accent colour per profile:** independent of the Home Assistant theme (button in the header, choice in the edit mode), six accent colours.
- **Dashboard panel, setup assistant:** three steps (look, which cards, an optional second view), shown once for a profile that has no saved settings; can be started again in the edit mode.
- **Dashboard panel, card "Today":** one card replaces the loose rows and the strip of open items (period start/end, LH test, temperature, pill, supplies). What is still open today is listed first, the rest sits behind "More". The doctor report moved into a menu; all texts in five languages.
- **Dashboard panel, jump bar:** a bar under the header jumps to Overview, History, Calendar, Supplies and Insights (only groups that are visible are shown). On the phone it sits at the bottom edge, with room for the iPhone safe area.
- **Dashboard panel, compact empty cards:** cards without data shrink to a single line instead of an empty box.
- **Dashboard panel, views:** create up to 8 named views (button next to the header), each with its own set of visible widgets, order, widths and folded state; switch with one tap, rename and delete in the edit mode. Without a view added, the layout behaves as before ("Standard").
- **Support card: packing list and school situations** (new switches `show_kit_list` and `show_school_scenarios`, both on by default): a tick-off list of what belongs in the bag (kept in the browser only) and five short tips for situations at school. Texts in five languages.
- **Pill pack start date** (new option "Start of the current pill pack" in the pill group of the options): the blister card places today in the pack from that date instead of guessing from the logged intakes, so starting to log in the middle of a pack no longer shifts the blister, and days without a logged pill show as empty cells. Later packs are assumed to follow without a gap; leave the field empty for the old estimate. The date also sets the "pill pack ends" calendar event and the shopping-list reminder (no logged intakes needed; during the break the next pack's end is used). Texts in five languages.
- **Welcome card for the first period** in the dashboard panel: shown once after the first period is logged (one start, at most 60 days ago) with what comes next; "Got it" hides it for that profile in this browser.
- **Card picker suggestions** (Home Assistant 2026.6): when you pick a cycle sensor in the "Add card" dialog, the gauge, compact status, calendar and (for profiles with a pill) pill pack cards are offered under "Community". Older versions ignore this.
- **Blueprint "Pill pack ending soon"**: runs your own actions a chosen number of days before the last active pill of the pack (uses the pack start date for an exact position).
- **Pill pack card**: the pill button is disabled while the intake is saved and a failed save now shows an error message instead of nothing; taken and not-logged days carry a symbol (check mark, exclamation mark) next to the colour, and a legend explains the four states (switch it off with `show_legend: false`). The card also has a visual editor now.
- **Sections view**: all cards declare a default and minimum width (`getGridOptions`), so they can be resized in the sections layout. The calendar, heatmap, history, statistics, inventory, gauge and support cards default to full width, the smaller cards to half.
- The dashboard panel shows the pill blister as the widget "Pill pack" (only for profiles whose current contraception method is the pill; reorder or hide it in the edit mode).
- In the dashboard panel's edit mode, the "Pill pack" widget shows a short note instead of nothing when the profile does not use the pill as its current contraception method.
- **Backup before deleting a removed profile's data:** the question in Settings > Repairs has a new answer, "Save a backup file, then delete everything". It writes `menstruation_removed_profile_<profile>_<date>.json` to the export folder (same format as the full backup, without the calendar-feed token), and only then deletes. If the file cannot be written, nothing is deleted and the dialog says so. After creating a profile with the same name again, `import_full_backup` restores it.
- **Repair "No recent backup":** once for the whole installation, when profiles hold data but no backup is newer than 90 days. A manual export, the copy of a removed profile and the snapshot the integration refreshes before every Home Assistant backup all count, so regular Home Assistant backups never trigger it. Checked daily; "Ignore" turns it off.
- **Event entity "Cycle events"** (`event.menstruation_<name>_cycle_events`): fires `pill_taken`, `lh_positive` and `ovulation_confirmed` (with the `date`) at the same moments as the bus events of the same names, so it can be picked as a trigger in the automation editor. Unavailable below visibility "Full", like the events themselves.
- **Temporary visibility change:** `set_profile_visibility` has the new optional field `revert_after_minutes` (1 to 1440). The previous level comes back after that time, also after a restart of Home Assistant (the due time is stored). Calling the service without the field, or again with a new time, replaces a pending revert; a second temporary change still restores the level from before the first. Example for guests: `level: private`, `revert_after_minutes: 120`.
- **Forecast window on the cards:** the gauge card, the compact status card and the compact cycle card show the window in which the next period is expected (for example "expected Nov 12 – Nov 16", from the spread of your recent cycle lengths) below the countdown or cycle day. It is hidden when the window is a single day, when it is already over (overdue period), and while pregnant or before the first period. The dashboard panel showed it already.
- **"Today" line in the Symptom insights widget** of the dashboard panel: names the symptoms you log more often in the phase the cycle is in right now (for example "Today (luteal), logged more often: Headache, Tender Breasts"). It only describes your own log, never advises, respects hidden symptom categories and is left out when there is no matching pattern.
- **Pain strength:** new optional symptom field `pain_intensity` (whole number 0 to 10, one value per day, `null` clears it) for `add_symptom` and `import_symptom_history`. Number field in the day form of the gauge and calendar card and in the quick log of the dashboard panel. A day with a strength of 1 or more counts as a pain day, also without pain types. The doctor report shows average and maximum strength per cycle, the wellness score weights pain days by strength, and the statistics card shows the average strength in the tooltip of the pain trend.
- **Dashboard panel: compact status card and small cycle card** as widgets "Status" and "Cycle & quick log" (hidden by default, switch them on in the edit mode; not shown in discreet mode).
- **Statistics card, cycle comparison:** shows the last six cycles (was three) and marks pain days per cycle (darker bar = stronger pain).
- **Dashboard panel animations:** cards fade in once when the panel opens, the numbers at the top count up, dialogs and messages slide in. Switch them off with "Animations" in the edit mode; "reduce motion" in the system is respected as before.
- **Dashboard panel, edit mode on the grid** (model: the macOS widget editor): cards can be dragged to reorder them, resized in width by dragging the lower right corner (3 to 12 of 12 columns, snapping), hidden with a small X in the corner and brought back from the list of hidden widgets. On touch screens only the grip at the top moves a card, so the page still scrolls; arrow keys work on a selected card. The edit bar with Save / Cancel stays in view while scrolling.
- **Dashboard panel: fold cards** by clicking the title (kept per profile), **chart period** (default, 3, 6, 12 months, all) for the cycle history, long-term trend, pain and mood chart, a strip **"Open today"** (temperature, LH test, pill with one tap, low stock; not in discreet mode), a **sticky header** and a **print view** with a print button.

### Changed
- **Shorter options page on Home Assistant 2026.11 and newer:** settings that only matter while a switch is on are hidden while it is off: everything about notifications (targets, time, the single reminders and their lead days) while "Notifications" is off, the lead days and times of a reminder while that reminder is off, the pill reminder time, follow-up and gap warning while the pill reminder is off, and the partner content of the calendar feed while the feed is off. Hidden settings keep their stored values and come back unchanged when the switch is turned on again. Older versions show the whole page as before. The integration now declares the category "Health and wellbeing" (Home Assistant 2026.11 shows integrations by category).
- Removing a profile now also deletes its export files with the default name (doctor report, wall calendar, history export). Files saved under a name you chose and the full backup are left alone.
- Removing a profile no longer leaves its stored data behind unnoticed: a notice in Settings > Repairs asks what to do with it (delete everything, delete everything except the cycle history, or keep it). Nothing is deleted until you answer; creating a profile with the same name again uses the data again.
- The translation loader no longer tries the legacy `/hacsfiles/` path (the integration serves its own files, so the HACS Marketplace in Home Assistant 2026.11 does not affect it).

### Fixed
- The saved visibility of dashboard cards now only keeps known cards (an imported or old entry with other keys is dropped).
- **Dashboard panel on the phone:** the page no longer scrolls sideways (cards in the grid and product rows could be wider than the screen).
- Dashboard panel: the full symptom history was loaded once per session and never refreshed, so a just logged temperature or LH test only showed up in the quick rows after a reload. It is now reloaded when the sensor state changes.
- New profiles got entity IDs like `sensor.anna` instead of `sensor.menstruation_anna` on Home Assistant 2026.10 (which no longer reads the attribute the integration used to propose the ID), and a "rename entities" repair appeared right after setup. All entities now propose their ID through `entity_id`; profiles that already exist keep theirs. Found by running the integration in a real Home Assistant (`tools/real_ha/run.sh`).
- Without the recorder loaded, every save of the history logged a warning with a traceback from the cycle statistics sync; the sync now skips quietly when the recorder is not set up. Found by calling every service in a real Home Assistant.
- The calendar could re-arm its start/end timer on an already removed entity when a profile was unloaded or reloaded while the events were being refreshed (about one test run in five on Home Assistant 2026.10 showed it as a lingering timer). The refresh now checks that the entity is still there before writing its state.
- Long-term statistics (cycle length, pain days per cycle, basal temperature backfill) now declare `mean_type` and `unit_class` instead of the removed `has_mean`. Home Assistant 2026.11 requires both and logged "will stop working in 2026.11" for the integration on 2026.10; older versions accept the new fields as well (checked on 2026.3, 2026.10 and 2026.11 against a real recorder).
- Options page: the four entity pickers (notification target, partner target, linked person, basal temperature sensor) were saved with an empty default that Home Assistant's validation rejects, so the options could not be saved without a notification target and a set target could not be cleared again. The set value is now shown as a suggestion and an empty picker stays empty.
- Notifications: a notify service that exists but fails (phone unreachable, error in the service) was never noticed, because the call did not wait for the result. The repair issue "Notifications cannot be delivered" only appeared when the service was missing altogether, and a failing partner target produced no warning. The calls now wait for the result, so both cases are reported as described.
- The full backup (`export_full_backup` / `import_full_backup`) left out the countdown timer state of each profile and the shared household inventory (stock, thresholds, consumption log), although the service is described as a backup of the complete stored data. Both are now part of the file and come back on import: "overwrite" replaces them, "merge" only fills them in while the profile has no saved timer and the inventory is still untouched. Backup files written by earlier versions import as before. Found by a round trip test (export, wipe, import).
- The description of `add_symptom` did not list the fields `discharge` and `smell`, although they were accepted.
- The calendar card legend showed "Period<" with a stray character.
- Statistics, inventory and compact cycle cards show a visible focus outline for keyboard use; those cards and the history and compact status cards respect the system setting "reduce motion".
- The cycle history table has column header scopes and a caption for screen readers.
- The quantity fields of the product inventory card have accessible names (product and action), so screen readers no longer announce unlabeled number inputs.
- The countdown timer card no longer asks for the browser notification permission as soon as it loads; the question appears when you start a timer with reminders on.
- The diagnostics download no longer shows the pill pack start date and shows the span of the logged cycle history in days instead of its first and last date.
- Two user-facing texts (`strings.json` and `translations/*.json`) still described the old behavior: the description of the option "Public ICS calendar feed" now mentions the dashboard button "New feed URL" for invalidating a shared URL, and the description of the service `set_profile_visibility` now says that below visibility "Full" the services that return a profile's data answer administrators only (as in `services.yaml`).
- Reconfiguring a profile (name, icon, onboarding stage) no longer reloads the entry from inside the config flow while an options update listener exists, which Home Assistant deprecated in 2026.6 and turns into an error in 2026.12. The listener now reloads the entry itself when one of these values differs from the running profile; saving the options wizard still does not reload.
- The Symptom insights widget of the dashboard panel showed raw keys such as `pain:headache` instead of the symptom name. It now shows the translated name.

## 1.9.1

### Added
- **Size comparison per pregnancy week:** from week 4 the pregnancy card in the dashboard panel shows one sentence for the current week ("Your baby is now about the size of a fig."), and the optional weekly pregnancy message ends with the same sentence. Text in all five languages (`baby_size_w4`..`baby_size_w40` in `www/translations/*.json`, shared by the card and the message). Next to the existing small icon the card now also shows the detailed baby illustration of the month (`assets/pregnancy/month_1..9.svg`, optimised to about 2.6 MB in total). The `preg_NN.svg` icons, the image entity and the other cards are unchanged.
- **Notification "Recurring symptom"** (option `notify_pattern_hint`, off by default): up to 2 days before a symptom you logged yourself usually shows up (headache, migraine, cramps, tender breasts, lower back pain, bloating, breakouts, low energy, poor sleep), one neutral message per symptom and cycle ("you often logged headaches on cycle days 8-9 (5 of your last 6 cycles). That window starts tomorrow"). Needs at least four logged cycles; the days are counted from the period start in the first half of the cycle and back from the next period in the second half. Only your own notification target, never the partner; no message during pregnancy, postpartum, menopause or before the first period. Plain counting of your own entries, no diagnosis (`recurring_symptom_patterns` in `model.py`).
- **Pill blister card** `custom:menstruation-pill-card`: a 28-day blister (taken pills filled, pause days gray, missed days outlined); tapping today's pill logs the intake. Backed by the new `pill_pack` sensor attribute (`pill_pack_view` in `model.py`, only with the pill as current method and visibility "Full"). Texts in five languages.
- **Printable wall calendar:** service `menstruation_cycle.export_wall_calendar` writes a one-page year calendar (HTML, A3 landscape print layout) to the export folder next to the doctor report and returns it as `html`: logged period days, expected periods, estimated fertile days and ovulation, a small dot for days with logged symptoms. Options `year`, `language` (de, en, es, fr, sv) and `title`; same permission as the other read services (`wall_calendar.py`).
- **"Your journey so far" for the pre-menarche stage:** below the sign checklist in the dashboard panel, the logged signs appear in the order they were first noticed ("Physical changes: stage 2, 7 months ago"), ending with an open "First period" step. No date is predicted there (the estimate above stays the only one); once breast development is logged, one general sentence says the first period comes about two years later on average, earlier for some and later for others. Texts in five languages.
- **Partner link for the ICS feed:** "Copy partner link" in the dashboard (next to "New feed URL", administrators only) gives a second, reduced calendar URL with only the predicted periods and the fertile window (no ovulation day, checkup, contraception/pregnancy dates, logged periods, reminders or source/confidence notes, apart from the "rough estimate" note below). It is derived one-way from the profile's ICS token, so the full-feed token cannot be computed from it, and it stops working whenever the token is rotated or renewed. "New partner link" (websocket command `rotate_ics_partner_token`) renews only the partner link. The new option "Partner link content" limits it to periods and fertile window (default), only the fertile window, or only the periods. The websocket commands `ics_url` and `rotate_ics_token` return it as `partner_url`.
- The dashboard shows when the calendar feed and the partner link were last fetched (`last_fetch` in the same commands; kept in memory, so it starts empty after a restart).

### Changed
- **Admin-only services:** `erase_all_history`, `import_full_backup` and `repair_storage` (which reports on every profile, whatever its visibility) can only be called by administrators and by automations. Logging periods and symptoms, the additive imports and the exports stay open to every user, since the cards and the app use them.
- **Read services below visibility "Full":** `get_symptom`, `get_full_history`, `get_cycle_predictions`, `compare_current_cycle`, `get_last_cycle_summary`, `get_menarche_info` and `export_doctor_report` now return a profile's data below visibility "Full" only to administrators (and to calls without a user, such as automations); other users get an error. Until now any Home Assistant user could read a "Private" profile through them. The service `set_profile_visibility` can only be called by administrators (and by automations), so a user cannot raise a profile's level first.
- The fertile window and ovulation events in the calendar entity and the ICS feed (including the partner link) carry the note "Rough estimate: too little logged data for a precise forecast yet" while the sensors still withhold the forecast (5 languages). The feed also asks calendar apps to refresh every 12 hours (`REFRESH-INTERVAL`, `X-PUBLISHED-TTL`).
- The README has a new section "Who can see what" with the visibility levels and permissions at a glance.
- The ICS feed is served with an ETag (`304 Not Modified` for unchanged content) and built once per day and data state instead of on every request.
- **ICS feed token:** every time the feed is switched from off to on, a new token is created, so URLs from earlier versions (when the token was published as the `ics_url` attribute) or from an earlier period of use never work again. Administrators can also rotate the token at any time with the new "New feed URL" button next to the "Subscribe to calendar" link in the dashboard (admin-only websocket command `menstruation_cycle/rotate_ics_token`); the old URL stops working immediately. The README explains how to invalidate a URL.
- The events `menstruation_cycle_pill_taken`, `menstruation_cycle_lh_positive` and `menstruation_cycle_ovulation_confirmed` (and so their logbook entries) are only fired at visibility "Full" instead of "Full" and "Status only", because the logbook is readable by every user. Automations that rely on these events for a "Status only" profile need visibility "Full".
- **Visibility "Status only" / "Private" now covers more places** (follow-up to the event change above). Below visibility "Full": the basal-temperature sensor and the "Period products today" sensor are unavailable (like the next-ovulation sensor); the hospital-bag to-do list is unavailable even during a pregnancy (its presence revealed one); `prediction_gating` shrinks to `precision_allowed` and `confidence` (cycle count, spread, logged entries and the `missing` hints stay at "Full"); the basal-temperature statistics backfill is skipped; and logging product use still lowers the household stock but no longer names the profile in the household log or fires `menstruation_cycle_product_consumed` (and so no logbook entry). Entries already in the household log keep their names.

### Fixed
- Export files (doctor report, wall calendar, history export, full backup) are written readable by the Home Assistant user only: created with mode 0600 right away (no chmod afterwards) and never through a symlink. The wall calendar title is limited to 100 characters and its page carries a Content-Security-Policy that allows no scripts or external loads.
- The ICS feed route compares the token in constant time.
- The calendar entity, the cycle-phase image, the ICS feed and the household overview built their cycle model without the profile's NFP mode (and, for calendar/image/feed, without its onboarding stage). A profile set to "strict" therefore got a predicted fertile window, ovulation day or "fertile" state there that its sensors correctly withhold. They now use the same NFP mode as the sensors, and the pre-menarche / early-menarche stages of the profile. For an established cycle the calendar, feed and image still show their estimated fertile window while the sensors withhold it for lack of logged cycles.
- The read services `get_symptom` and `get_menarche_info` no longer write the returned health data to the Home Assistant log.

## 1.9.0

### Added
- Cycle comparison in the NFP tab of the statistics card: the temperature curves of the last three cycles over one cycle-day axis, with a marker row per cycle for period days, positive ovulation tests and stretchy mucus (reads the full history, 5 languages).
- Data-quality hints: `prediction_gating.missing` lists what holds the forecast back (more finished cycles, strongly varying cycle lengths, too few recent log entries, no recent temperature, too few cycles with a confirmed temperature rise for the own luteal-phase forecast). The dashboard shows them under the learning-phase note (5 languages).
- Doctor report: the statistics card now opens the report straight away (open/download link) instead of only saying it was saved to the export folder; `export_doctor_report` returns `filename`, `path` and `html` as a service response. The hard-coded German hint is translated.
- Countdown/timer card: all remaining hard-coded German texts (product selector, timer buttons and status, pregnancy/postpartum/menopause lists, moods, wellness tips, notification) now come from the translation files (DE/EN/ES/FR/SV); a guard test keeps new German literals out of the cards.
- Protection against accidental period starts: the dashboard panel asks before a period is started less than 15 days after the last period day (with the option to log it as bleeding between periods instead), the calendar and gauge cards ask before a tapped day 3-14 days after the previous period day opens a new period, and `repair_storage` / the storage-integrity repair issue flag period starts of the last year that follow the previous one within 14 days.
- Notification option "Pregnancy test timing hint" for people trying to conceive: 14 days after an ovulation confirmed by the temperature/mucus analysis, one neutral message (a rule of thumb, no medical advice), once per cycle; off by default.
- Dashboard panel: a small line "Open notes about your data: N" (linking to Settings > Repairs) shows how many of the integration's repair issues are open; hidden in discreet mode and whenever the count cannot be read.
- Dashboard panel: a "Create doctor report" button creates the report right in the panel (saved to the export folder as before) and shows an open/download link; the period (3, 6 or 12 months) and an optional patient name can be chosen there (the name is only kept in memory); the report is created in the panel language (English if the language has no report).
- Household supplies vs. the next period: a repair issue "Supplies may not last the next period" appears when a period is predicted within 7 days (private profiles are ignored) and the stock of tampons, pads or liners is below what the household typically used per period (average of the last up to 3 finished periods in the consumption log, at least 2 needed; a running period is left out). It clears as soon as the stock is topped up or no period is near. A rule of thumb, not a purchase order.
- The "supplies may not last the next period" warning also shows in the product inventory card and the dashboard panel (household sensor attribute `supply_short`, only filled while a period is near).
- Positive LH (ovulation) test as ovulation anchor: in hybrid mode a positive `test: positive_ovulation` entry in the current cycle moves the ovulation estimate to the day after the first positive test (fertile window 5 days before through 1 day after) whenever no temperature analysis with high or medium confidence exists. A confirmed temperature rise still wins; strict mode is unchanged; the forecast source stays `estimated`.
- Learned ovulation pattern also uses positive LH tests: in earlier cycles without a temperature rise, the day after the first positive `positive_ovulation` test counts as ovulation day (same plausibility range, day 8 to 25), so LH-only users get a learned offset too.
- Notification "Ovulation test start" (option `notify_lh_hint`, off by default): once per cycle, 7 days before the expected ovulation, one neutral message that now is a good time to start ovulation (LH) tests; a positive LH test or confirmed ovulation moves the estimate and so suppresses it. Texts in 5 languages.
- Notification "Basal temperature" (option `notify_temp_reminder`, off by default): from the start of the fertile window until 3 days after the expected ovulation, and only while no temperature rise is confirmed, reminds people who log their temperature regularly (3 of the last 7 days) to measure and log it when today's value is missing. Texts in 5 languages.
- Option `notify_period_luteal` (off by default): "Period expected" uses the date from your own luteal phase length (ovulation plus learned luteal phase) as soon as it exists; otherwise it stays with the calendar date. The reminder is still sent once per date. With the option on, the "period overdue" hint and the repair notice count from the same luteal date.
- `fertility_forecast.source` is now `lh` (confidence `medium`) when the forecast is anchored on a positive ovulation test instead of `estimated`; the statistics card shows "Ovulation test (LH)" (5 languages) and the iCal feed names it. Weighting of the date-range forecast is unchanged.
- Event `menstruation_cycle_lh_positive` (data: `entry_id`, `profile`, `friendly_name`, `date`) when the first positive ovulation test of a cycle is logged (not for private profiles, not on repeats or bulk imports), with a translated logbook entry (5 languages) and the blueprint "Action on positive ovulation test".
- Event `menstruation_cycle_ovulation_confirmed` (data: `entry_id`, `profile`, `friendly_name`, `date` of the temperature rise) when a sensor update newly confirms the rise of a cycle (once per cycle, not for private profiles; the last confirmed cycle is remembered across restarts, so a restart neither repeats the event nor loses one confirmed while Home Assistant was down), with a translated logbook entry (5 languages) and the blueprint "Action on confirmed temperature rise".
- New option "Calendar: period from the luteal phase" (`calendar_luteal_forecast`, off by default): the period date calculated from your own luteal phase length appears as an all-day event in the calendar entity (visibility "Full") and in the ICS feed while it lies in the future.
- New option "Calendar: ovulation from your logs" (`calendar_ovulation_events`, off by default): for each cycle of the last 12 months, the ovulation day your own logs show appears as an all-day event in the calendar entity (visibility "Full") and in the ICS feed - the confirmed temperature analysis if there is one, otherwise the day after the first positive ovulation test - with the source in the description. Texts in 5 languages.
- Dashboard panel: quick entry for today's basal temperature below the LH buttons, offered to people who logged a temperature in the last 14 days (not in discreet mode or in other life stages). The unit (°C/°F) is checked by the service, whose message is shown on a wrong value. Texts in 5 languages.
- `nfp_analysis` now also carries `lh_first_positive_day` (first positive ovulation test of the running cycle) and `lh_anchored` (true while that test sets the ovulation estimate, i.e. the forecast source is `lh`) for templates; the dashboard panel shows "Positive ovulation test on …" under the ovulation estimate in that case (5 languages).
- The sensor publishes the profile's temperature unit as attribute `temperature_unit` (full visibility only). The dashboard panel, the statistics card (temperature curve axis and threshold caption) and the day dialog of the calendar and gauge cards (label, prefilled value, range, placeholder) use it and show °F for Fahrenheit profiles (values stay stored in °C; the day dialogs send the typed value as entered, the service interprets it by the profile unit).
- The pregnancy-test timing hint (`notify_test_hint`) also works for LH-only users: without an NFP-confirmed ovulation, the day after the first positive LH test of the cycle counts as ovulation (own text in 5 languages: "estimated from your positive LH test"). A confirmed ovulation still takes precedence.
- Doctor report: the cycle overview gets an "Ovulation signs (cycle day)" column with the cycle day of the first positive LH test and of the temperature rise (e.g. "LH 12 · Temp. 15"); it only appears when at least one analysed cycle has such a signal, in all 5 report languages. `cycle_table` rows gain `lh_day` and `temp_rise_day`.
- Next-period forecast from the personal luteal phase: once the temperature rise of the running cycle is seen and at least two finished cycles with a rise exist, `nfp_analysis.luteal_forecast` holds `predicted_start` (rise day plus the average luteal phase), `luteal_days` and `difference_days` against the calendar prediction, and the NFP tab of the statistics card shows the date. The regular next-period prediction is not changed.
- Doctor report: new line "LH test and temperature rise" with the average, minimum and maximum number of days between the first positive LH test and the temperature rise (cycles with both signals, plausible range -3 to +7 days), in all 5 report languages. Not shown in the statistics card.
- Repair hint after a positive pregnancy test: when the most recent pregnancy test entry is positive (a later negative test clears it), within 14 days and pregnancy mode is off, a neutral informational repair issue points to the pregnancy mode (dashboard panel or `set_pregnancy_mode`). It is raised right after saving, at setup and at midnight, can be dismissed and changes nothing automatically. Texts in 5 languages.

### Changed
- Translation files are served gzip-compressed and with an ETag, so the per-request revalidation costs a 304 without body instead of re-sending about 70 KB.
- The dashboard panel is no longer registered as a Lovelace resource (the sidebar panel loads it itself), so its 455 KB is not fetched on every dashboard page. Existing resource entries for it are removed automatically.
- **Calendar feed (ICS) is now opt-in per profile and off by default** (option "Public ICS calendar feed"). The secret feed URL is no longer published as the `ics_url` state attribute (it was visible to every user through states, history and templates); administrators get it through an admin-only websocket command that the dashboard panel uses for its "Subscribe to calendar" link. A disabled feed, an unknown token and a `private` profile all answer 404. Existing installations: switch the option on per profile to keep using a subscribed feed (the token and URL stay the same); the stale-token repair issue only appears while the feed is on. Breaking for anything that read the `ics_url` attribute.
- Faster and lighter: the cycle model is calculated once per profile and day and reused while history, symptoms and options are unchanged (the sensors, the phase image, the calendar, the notifications and the household supply check used to calculate it separately; the next-ovulation sensor update drops from about 8 to 0.3 ms with three years of data). A change refreshes only the affected profile's entities instead of every profile's, and the sensors are updated once instead of twice. The card and panel JavaScript is served gzip-compressed (about 75 % less transfer, compressed once and kept in memory).
- Dashboard panel renders about 60 times faster (72 ms to about 1 ms for a full render in a desktop Node measurement): every translation lookup used to copy the whole English dictionary twice, and every date was formatted with a fresh Intl formatter. Same output as before, checked byte for byte in four languages. Badge evaluation and date parsing in the main sensor are faster too (warm update 5.0 to 3.4 ms with three years of data).
- The dashboard panel no longer loads Google Fonts at runtime (no third-party request, no visitor IP sent to Google); installed fonts are used, system fonts otherwise.
- 28 services that were only described in English now have names, descriptions and field labels in DE/EN/ES/FR/SV.
- Card texts that fell back to English in German (calendar, statistics, support, history, timer cards) are translated; dashboard texts were completed in ES/FR/SV.
- Cards and dashboard panel now load the translation file of any language that has one (Spanish, French and Swedish were never loaded before); other languages use English.

### Fixed
- Lovelace resources were registered again on every Home Assistant start (the resource list was read before it was loaded, so it looked empty). The list is now loaded first, and identical duplicate entries left over from earlier starts are removed automatically (#256).
- No blocking file I/O on the event loop any more: diagnostics reads the version without touching `manifest.json`, the HTTP handlers for card, asset and translation files and the cycle-phase image entity check and read files in the executor.
- Countdown/timer card: the "time is up" browser notification threw an error (a `Notification` has no `.catch`), so the alert sound and the automatic reset were skipped; on browsers without the Notification API (iOS Safari) the card even showed its load-error state.
- Several places used the system clock (`date.today()`) instead of Home Assistant's time zone to decide what "today" is (cycle model at the midnight run and on load, calendar, ICS feed, hospital-bag reminder, cycle predictions, date checks in the options form); around midnight they could work with the wrong day. A test now guards against it.
- The basal-temperature import from a linked sensor only ran at midnight and on load, when the sensor still held yesterday's value: that value was stored under the new day and blocked the real morning reading. The import now runs when the sensor updates (and when the option is saved), stores a reading under the day it was taken, and ignores readings older than yesterday.
- The renewal reminder for an IUD, implant or injection counted from the very first log of the method, so re-logging the same method after a renewal (for example every injection) left it overdue forever. A confirmed renewal now restarts the period.
- The shopping-list text for the renewal showed the internal method key (`hormonal_iud`); it now uses the localized name, and items written by older versions still count as duplicates.
- The cycle insights widget showed the raw text `dashboard_cycle_comparison_basis` instead of "based on N cycles" (translation was missing in all languages). A test now checks that every literal key used by the panel is translated.
- hassfest rejected the service descriptions of `export_history` and `export_doctor_report` (the text `<config>` looked like HTML); the same placeholder was also removed from the calendar option text in DE/ES/FR/SV.
- The repair dialogs of the three fixable issues (rename entities, rotate calendar token, migrate old integration) opened empty after clicking "Fix" because the form texts (`fix_flow`) were missing in all languages; they are added now, and the rename list is shown as a bullet list. For these issues the text now lives only in the fix form (hassfest does not allow both `description` and `fix_flow`). Tests check that every fixable issue has its form text and that the flow supplies its placeholders.
- The statistics, gauge and calendar cards read `symptom_history` and `product_usage_timeline` only from the sensor attributes, which are dropped when a profile has a lot of data (the heatmap and the dashboard panel already reloaded them). The cards now fetch the lists with `get_full_history` when the attribute is missing, so the symptom distribution, the past symptom dots and the product timeline stay filled.
- The harmless Lovelace-helper import message in the debug log no longer prints a traceback.
- Logging a bleeding strength as a symptom (the only way in the dashboard panel) only continued a running period and never started a new one, so a bleeding without a logged period start stayed without a period. It now starts a period when no period day was recorded in the 14 days before and the profile is not pregnant; bleeding closer to the last period still counts as intermenstrual.
- The countdown/product timer card in the dashboard panel stayed empty ("IDLE") because the panel passed no entity to it; it now gets the selected profile's main cycle sensor.
- The calendar card read the symptom entries as nested objects although they are stored flat, so the dot for days with logged symptoms never appeared (and the edit dialog's fallback was empty); both shapes are accepted now.
- `import_full_backup` did not restore the hospital-bag checklist, although `export_full_backup` wrote it.
- The diagnostics download exposed the partner notify target, the basal-temperature sensor entity and a legacy profile name; they are redacted now.
- Services `compare_current_cycle`, `export_doctor_report`, `get_cycle_predictions`, dashboard-preference, household-summary, profile-visibility and basal-temperature reimport services stayed registered after the last entry was removed.
